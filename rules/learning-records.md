# 学习记录规则

## 目录职责

- Notion 工作区「私人学习」：学习记录的主存储位置。
- `docs/notion-private-learning.md`：Notion 不可用时的待同步草稿。
- `learning/daily/`：本地每日学习成果、关键问题、练习和复盘。
- `learning/progress.md`：本地总体学习进度和里程碑。
- `learning/mistakes.md`：本地错题本，记录误解、纠正和复测状态。
- `learning/todo.md`：本地待办事项，记录下一步学习和项目任务。
- `docs/agent-architecture.md`：本地智能体总体架构沉淀。

主记录优先写入 Notion；本地文件作为备份、草稿和无法访问 Notion 时的同步来源。

## 每日记录格式

每日文件命名：`YYYY-MM-DD.md`。

建议包含：

- 今日主题
- 苏格拉底问题
- 我的回答
- 纠正与补充
- 今日成果
- 今日练习
- 待复习点

## 进度规则

更新 `learning/progress.md` 时，保持三个层级：

- 当前阶段
- 已掌握
- 下一步

## 错题本规则

错题必须包含：

- 错误理解
- 正确理解
- 触发场景
- 复测问题
- 状态：待复测 / 已掌握

如果某个错题下次回答正确：

- 从当前错题本的待复测列表移除。
- 在学习记录里保留“已纠正/已掌握”的历史摘要。
- 不再把它作为不清楚知识点展示。

## Todo 规则

todo 使用复选框：

- `[ ]` 未完成
- `[x]` 已完成

每个 todo 尽量写成可验证动作。

## Notion 记录规则

每当一个知识点学习完成后，优先在 Notion 工作区「私人学习」更新：

- 本次学习了哪些内容。
- 当前学习到哪里。
- 接下来学习什么。
- 已经知道和掌握的知识点。
- 不清楚、需要复习或需要复测的知识点。
- 错题本：错了要记录，下次答对就从待复测错题本移除。
- 本工作区规则，包括教学方式、记录方式和协作偏好。

建议 Notion 结构：

- 页面：`智能体学习总览`
- 子页面或数据库：`每日学习记录`
- 子页面或数据库：`学习进度`
- 子页面或数据库：`错题本`
- 子页面或数据库：`Todo`
- 子页面：`协作规则`

## 本地同步规则

如果当前环境不能直接写入 Notion：

- 先更新 `docs/notion-private-learning.md`，把要写入 Notion 的内容完整整理好。
- 同步更新 `learning/` 下的本地学习记录，避免信息丢失。
- 明确告诉学习者：Notion 尚未实际写入，当前只是待同步草稿。

## GitHub 规则

GitHub 不再作为学习记录的主存储位置。

- 除非学习者明确要求，知识点完成后不再因为学习记录自动提交并推送 GitHub。
- 如果修改了本工作区规则、代码或文档结构，可以根据任务需要提交 GitHub。
- 如果无法写入 Notion，可以用 GitHub 暂存规则变更，但要说明它不是学习记录主渠道。
