## 今日主题

初始化智能体学习体系；区分普通 LLM 调用、工作流和智能体；理解智能体最小闭环。

## 苏格拉底问题

1. 你认为“智能体”和“普通调用一次大模型接口”的根本区别是什么？
2. 如果一个智能体会调用工具，谁来决定什么时候调用、调用哪个工具、如何处理失败？
3. 你希望第一个实战智能体解决什么具体问题？

## 我的回答

1. “问 ChatGPT 一个问题，它回答你”不算智能体。
2. 固定执行 `读取文件 -> 总结 -> 生成报告` 更像工作流。
3. 智能体比普通 LLM 调用多出的关键能力是“能真正执行”。
4. 最小智能体应该有一个流程，每个流程节点通过 LLM 根据上一个节点得到的结论判断接下来的走向，最终输出一个稳定结论。

## 纠正与补充

- 前两个判断正确：一次问答通常只是普通 LLM 调用；固定步骤执行更接近工作流。
- 第三个回答方向正确，但需要更精确：智能体不只是“能执行”，而是能围绕目标，根据上下文和状态决定下一步，必要时调用工具，观察结果，再决定继续、重试或结束。
- 简单边界：
  - 普通 LLM 调用：输入一次，输出一次。
  - 工作流：步骤预先固定，模型可能只是某些步骤里的处理器。
  - 智能体：目标明确，但路径可能动态变化，会决策、行动、观察并迭代。
- 最小智能体闭环可以表达为：目标输入 -> 状态/上下文 -> 决策 -> 行动/工具调用 -> 观察结果 -> 判断继续或结束 -> 输出。
- “稳定结论”不是只靠生成一次答案，而是要有停止条件：信息足够、任务完成、工具失败不可恢复、达到预算上限等。
