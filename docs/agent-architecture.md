# 智能体总体架构

这个文件用于长期沉淀智能体架构，不一次性写满。每完成一个阶段，就补充一层。

## 1. 最小智能体闭环

```text
用户目标
  -> 输入理解
  -> 状态 / 上下文
  -> 决策
  -> 工具调用
  -> 结果观察
  -> 输出或继续行动
```

### 1.1 与普通 LLM 调用、工作流的区别

- 普通 LLM 调用：输入一次，输出一次，系统本身不持续追踪任务状态。
- 工作流：步骤和顺序由代码或流程预先固定，模型通常只是某个节点的处理器。
- 智能体：围绕目标运行，能根据状态和工具结果动态决定下一步行动。

### 1.2 最小闭环六要素

- 目标：用户要完成什么。
- 状态：当前已知信息、已执行步骤、中间结果和限制。
- 决策：下一步做什么，是否需要调用工具。
- 行动：执行模型输出、工具调用、文件操作或其他外部动作。
- 观察：读取行动结果，判断是否有效、是否失败、是否需要补充信息。
- 停止条件：任务完成、信息足够、失败不可恢复、达到预算或需要人类确认。

## 2. 核心模块

- 模型：负责理解、推理、生成和工具选择。
- Prompt / 指令：约束角色、目标、边界和输出格式。
- 工具：让智能体访问外部能力，例如搜索、数据库、代码执行、文件读写。
- 状态：记录当前任务进展、变量、步骤和中间结果。
- 记忆：保存跨任务可复用的信息。
- 工作流：控制智能体如何在步骤之间流转。
- 评估：判断智能体是否稳定、正确、可控。
- 观测：记录日志、轨迹、成本、延迟和错误。

### 2.1 状态与记忆

- 状态：一次任务运行中的当前进展，包含目标、已执行步骤、中间结果、工具返回、错误、预算和下一步依据。
- 记忆：跨任务保留的信息，包含用户偏好、长期事实、历史经验、可复用总结和项目背景。
- 关键区别：状态回答“当前这次任务走到哪里了”，记忆回答“以后还应该记住什么”。
- 设计原则：不是所有状态都应该进入记忆，只有未来可复用、稳定、经过确认的信息才适合长期保存。

## 3. 常见架构形态

- 单智能体：一个智能体完成理解、规划和执行。
- 工作流智能体：用显式流程或状态机控制每一步。
- 多智能体：多个角色分工协作，例如研究员、执行者、审查者。
- 人在回路：关键节点需要人确认或审批。
